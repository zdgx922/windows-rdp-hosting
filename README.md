## 先确认你的机器够不够格当主机

Windows 10/11 家庭版只能作客户端，不能作被控主机。主机相关的组件在家庭版里根本没有完整落地，改注册表也变不出来。手上只有家庭版又必须用 RDP，只有升级到专业版，或者放弃自带 RDP 改用 VNC 这类跨平台工具两条路。

专业版、企业版、教育版自带远程桌面主机功能。Windows Server 系列天生支持，但默认行为要提前知道：没安装“远程桌面服务”（RDS）角色时，服务器通常只允许同时存在两个并发的管理员远程会话。这是内置的“管理用远程桌面”设计，拿来跑正经业务不够用。

客户端系统（Win10/11 专业版）只允许一个交互式会话。第二个人连上来，系统会问要不要断开当前用户，选“是”前一个人就被顶下线。组策略里那个 `MaxConnectionCount` 改不了这件事，它是数量阀门，不是架构开关。

要让多人各用各的桌面，得部署 RDS 角色，一共四个：RD 会话主机负责承载用户会话，RD 授权管理 CAL，RD 连接代理做重连分配，RD Web 访问提供网页入口。小团队单台服务器，只装会话主机和授权两个角色就能跑起来。

授权这笔钱要提前算。会话主机每接受一个新连接都会向授权服务器查询对应的 CAL，网络里找不到可用授权服务器就进宽限期，**大约 120 天**，之后新会话直接被拒。CAL 分两种：固定一人一机选用户 CAL，一台设备多人轮流用选设备 CAL。买错方向，要么白花钱，要么人数一多就不够。

这段是整篇文章里最影响预算的部分。开个远程桌面开关是免费的，让五个人同时在线办公不是。

## 云服务器上把 RDP 打通：九步清单

这一步一步走下来，任何一步没对上，后面都白搭。

**1. 确认服务在跑。** 服务器 CMD 执行 `sc query TermService`，看到 `STATE : 4 RUNNING` 才算正常。

**2. 查实际监听端口。** `reg query "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp" /v PortNumber`。返回十六进制值就在 PowerShell 换算，比如 `[Convert]::ToInt32("c4d5", 16)` 得到 51389。这个 51389 只是某个案例里的实际端口，不是推荐值，你按自己机器返回的结果来。

**3. 确认端口在监听。** `netstat -ano | findstr :51389`，或者 `Get-NetTCPConnection -LocalPort 51389 -State Listen`。服务 RUNNING 不等于端口在听，这两件事要分开验证。

**4. Windows 防火墙放行。** 为实际端口建入站规则：`New-NetFirewallRule -DisplayName "RDP TCP" -Direction Inbound -Protocol TCP -LocalPort 51389 -Action Allow`。

**5. 安全组入方向。** 协议 TCP，端口填实际端口，源地址填你本地**当前公网出口 IP** 的 `/32`。填 `192.168.x.x`、`10.x.x.x`、`172.16.x.x` 这些内网地址完全无效，安全组看不懂它们。

**6. 云防火墙。** 如果服务器的弹性公网 IP 纳入了云防火墙防护，这一层要单独放行同样的来源、目的和端口。安全组和云防火墙是两个独立的控制层，只配一层、另一层拒绝，照样连不上。

**7. NAT/DNAT 映射。** 公网 IP 不是直接绑在机器上、而是走 NAT 网关时，检查 DNAT 规则。公网端口和服务器端口可以不同，连接时用公网那个。

**8. 本地验证。** `Test-NetConnection 服务器公网IP -Port 51389`，盯 `TcpTestSucceeded`。

**9. 发起连接。** `mstsc /v:服务器公网IP:51389`，或者在远程桌面连接的计算机栏直接写 `IP:端口`。只填 IP 不写端口，客户端会默认访问 3389。

有一条经验值得单独说：**堡垒机能进服务器，只证明内网路径正常，证明不了公网入口配对了。** 这两条是完全不同的网络路径，别用前者推断后者。

源地址还会变。家宽重播、公司网络、挂 VPN、切手机热点，出口 IP 都可能不同。昨天能连今天连不上，先怀疑白名单里那个 IP 过期了，别急着怀疑服务器。

## 改端口挡的是扫描脚本，不是攻击者

改注册表：`reg add "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp" /v PortNumber /t REG_DWORD /d 3390 /f`，然后 `Restart-Service TermService -Force` 或直接重启。

这一步会掐断所有现有远程会话，动手前确认自己还有控制台或堡垒机能进得去，否则就是把自己锁在门外。

改完记得在防火墙放行新端口，连接时写 `IP:3390`。

**改端口只能挡掉批量扫 3389 的脚本。** 真正盯上你的攻击者会扫全网端口，换个端口对他没有任何阻碍。真正管用的是下面这几条：

- 安全组源地址只放可信 IP 的 `/32`，不要长期 `0.0.0.0/0` 开放 RDP
- 强密码，限制可远程登录的账号范围，别让 Administrators 组里躺着一堆不用的账号
- 启用账户锁定策略和登录审计，被爆破时能看见
- 及时打补丁
- 有条件就走 VPN、堡垒机或零信任接入，把 RDP 从公网撤下来

## 连不上、被踢、被锁，分别查什么

| 症状 | 可能原因 | 处理方向 |
| --- | --- | --- |
| 一直“正在连接”，最后超时 | 端口不通：防火墙、安全组、云防火墙、NAT 任一层没放行 | 按九步清单从 TermService 一路查到 `Test-NetConnection` |
| 端口通但登录失败，提示“系统管理员已限制可以使用的登录类型” | 启用了 NLA，用户不在 Remote Desktop Users 组，或该组没有“从网络访问此计算机”权限 | `net localgroup "Remote Desktop Users" 用户名 /add`，或检查组策略的“从网络访问此计算机” |
| 连上就被秒踢 | 已有活动会话占位 | `qwinsta` 查会话，`logoff` 清掉“已断开”的残留会话 |
| 提示超过最大连接数 | Server 未装 RDS，撞上两个并发管理员会话的上限；或 RDS 授权异常 | 查 RDS 授权服务器和 CAL 状态 |
| 用了几个月后突然连不上 | RDS 宽限期约 120 天到期，授权服务器仍未配置 | 激活授权服务器并安装 CAL |
| 报“发生身份验证错误。不支持请求的功能” | CredSSP 加密 Oracle 修正导致的版本不匹配 | 见下方说明 |

CredSSP 那条报错要单独解释一下，免得你对着一篇 2018 年的老文章瞎改注册表。这是 2018 年 3、4、5 月那批安全更新修复 CVE-2018-0886 之后出现的问题。2018 年 5 月 8 日的更新把默认设置从“有漏洞”改成“已缓解”，此后打过补丁的客户端去连没打补丁、或者打了补丁没重启的旧服务器，就会报这个错。解决办法是更新并重启两端系统。2026 年新装的机器基本不会遇到，除非你在连一台多年没动过的老服务器。

另外，Windows 10 1709 在远程桌面已锁屏时要求输入两次密码，这个是 KB4343893（OS 内部版本 16299.637，2018 年 8 月 30 日）修掉的，同样是老版本才有的问题。

## 会话老是被锁、被断开

RDS 会话有四种状态：活动、空闲、已锁定、已断开。没有固定时间规律的断开，更可能是网络问题，不是配置问题。

**超时断开**由两个注册表值控制，位置在 `HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp`：`MaxIdleTime` 管空闲多久断，`MaxConnectionTime` 管总共能连多久，类型都是 `REG_DWORD`，**单位毫秒**。RDS 部署可以在“集合 → 属性 → 会话”里统一设，组策略路径是“管理模板 → Windows 组件 → 远程桌面服务 → 远程桌面会话主机 → 会话时间限制”。

**会话被锁**是另一套配置。一是安全策略“交互式登录：计算机不活动限制”，注册表值 `InactivityTimeoutSecs`，**单位秒**；二是屏幕保护程序，需要三个值同时生效：`ScreenSaveActive`、`ScreenSaverIsSecure`、`ScreenSaveTimeOut`，也是秒。

优先级记这一条就够：计算机策略优先于用户策略，策略优先于默认配置。

走远程桌面网关连进来的，超时还能在“RDGW 管理器 → 策略 → 连接授权策略 → 超时”里单独设，绕过网关直连的用户不受这个影响。

## 没有公网 IP 怎么办

家里或公司内网的机器想被外网连，又没有公网 IP，可以用 frp 做内网穿透。客户端从 GitHub Releases 下载对应架构的包，配好 `frpc.ini` 指向你有公网 IP 的服务端，运行 `frpc.exe -c frpc.ini`。

麻烦的是开机自启。直接双击运行，重启就没了。两种做法：用任务计划程序创建任务，安全选项选“不管用户是否登录都要运行”；或者用 NSSM 注册成系统服务，`nssm install frp`，`Arguments` 填 `-c frpc.ini`。后者更稳，服务挂了能被系统拉起来。

这条路的问题在于，穿透出来的端口最终还是暴露在公网上。安全组白名单那套做法在这里同样适用，别把 RDP 裸奔在穿透端口上。
